# S3 storage

By default entries are files in `STORAGE_DIR`. To keep them in an S3 compatible bucket instead, set `STORAGE_BACKEND=s3`. This lets several server instances share one cache and keeps the container itself stateless.

The server is tested against [Garage](https://garagehq.deuxfleurs.fr/) and [SeaweedFS](https://github.com/seaweedfs/seaweedfs). AWS S3 and Cloudflare R2 use the same API but are not part of the test suite.

## Configuration

```bash
STORAGE_BACKEND=s3
S3_BUCKET=nx-cache
S3_ENDPOINT=https://s3.example.com   # omit for AWS
S3_REGION=eu-west-1
S3_PATH_STYLE=true                   # most self-hosted services need it
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
```

Every variable is described on the [configuration page](../configuration.md#s3-backend). The bucket must exist: the server never creates it.

| Service       | `S3_ENDPOINT`                                   | `S3_REGION`  | `S3_PATH_STYLE` |
|---------------|-------------------------------------------------|--------------|-----------------|
| AWS S3        | unset                                           | your region  | `false`         |
| Cloudflare R2 | `https://<account id>.r2.cloudflarestorage.com` | `auto`       | `true`          |
| Garage        | `http://garage:3900`                            | `garage`     | `true`          |
| SeaweedFS     | `http://seaweedfs:8333`                         | `us-east-1`  | `true`          |

## Permissions

The access key needs these actions on the bucket:

| Action                                                            | Used for                                  |
|-------------------------------------------------------------------|-------------------------------------------|
| `s3:GetObject`, `s3:PutObject`                                    | Downloads, uploads, refreshing last use   |
| `s3:DeleteObject`                                                 | [Cleanup](../configuration.md#cleanup-and-retention) |
| `s3:ListBucket`                                                   | Cleanup and the existence check of uploads |
| `s3:AbortMultipartUpload`                                         | Dropping a failed large upload            |

An AWS policy for a bucket named `nx-cache`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::nx-cache"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:AbortMultipartUpload"],
      "Resource": "arn:aws:s3:::nx-cache/*"
    }
  ]
}
```

Without static keys, the AWS SDK also reads instance roles, pod identities and shared credential files.

## Docker Compose with Garage

A self-hosted setup in one file. Garage needs a small configuration file and a one-time layout, bucket and key setup.

```yaml
services:
  garage:
    image: dxflrs/garage:v2.5.0
    restart: unless-stopped
    volumes:
      - ./garage.toml:/etc/garage.toml:ro
      - garage-meta:/var/lib/garage/meta
      - garage-data:/var/lib/garage/data

  nx-cache:
    image: enxtur/nx-caching-server:latest
    restart: unless-stopped
    depends_on:
      - garage
    ports:
      - "8090:8090"
    volumes:
      - ./auth.yaml:/etc/nx-cache/auth.yaml:ro
    environment:
      - AUTH_CONFIG=/etc/nx-cache/auth.yaml
      - STORAGE_BACKEND=s3
      - S3_BUCKET=nx-cache
      - S3_ENDPOINT=http://garage:3900
      - S3_REGION=garage
      - S3_PATH_STYLE=true
      - AWS_ACCESS_KEY_ID=${GARAGE_KEY_ID}
      - AWS_SECRET_ACCESS_KEY=${GARAGE_KEY_SECRET}

volumes:
  garage-meta:
  garage-data:
```

`garage.toml` for one node (generate your own `rpc_secret` with `openssl rand -hex 32`):

```toml
metadata_dir = "/var/lib/garage/meta"
data_dir = "/var/lib/garage/data"
db_engine = "lmdb"
replication_factor = 1

rpc_bind_addr = "0.0.0.0:3901"
rpc_secret = "<64 hex characters>"

[s3_api]
s3_region = "garage"
api_bind_addr = "0.0.0.0:3900"
```

After `docker compose up -d garage`, create the layout, the bucket and a key once:

```bash
garage() { docker compose exec garage /garage "$@"; }

node=$(garage node id -q | cut -d@ -f1)
garage layout assign -z dc1 -c 10G "$node"
garage layout apply --version 1
garage bucket create nx-cache
garage key create nx-server        # prints the key id and the secret
garage bucket allow --read --write --owner nx-cache --key nx-server
```

Put the printed key id and secret in `GARAGE_KEY_ID` and `GARAGE_KEY_SECRET`, then `docker compose up -d`.

## Behavior to know

- **First upload wins.** The server checks that the object is absent and sends `If-None-Match: *`. Services that enforce the header (AWS S3, SeaweedFS) make this atomic. Garage ignores it, so two simultaneous uploads of the same key can both succeed and the last one stays.
- **Large uploads are streamed.** The request body is sent to the bucket in 8 MiB parts, at most three at a time, so an upload holds about 24 MiB of memory whatever its size.
- **Cleanup is done by the server.** Retention is per scope kind, which bucket lifecycle rules cannot express. A download refreshes the entry with a copy onto itself when it is older than a quarter of the shortest retention. Do not add lifecycle rules that expire these objects.
- **Failed large uploads** are aborted by the server. If the process is killed mid-upload, parts can remain: a lifecycle rule that aborts incomplete multipart uploads after a day cleans them (`AbortIncompleteMultipartUpload` on AWS and R2).
